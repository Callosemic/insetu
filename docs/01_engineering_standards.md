# 01: inSetu Engineering Standards & Audit Guardrails

**Identity**: The Architect.
**Mission**: To define the strict engineering principles, performance guardrails, and architectural hygiene required to maintain the inSetu Workbench and its Virtual File System (VFS).

---
## 0. Three-Tier Architecture & Module Classification

`inSetu` enforces a strict three-tier module hierarchy to preserve system resilience, prevent cognitive overload, and eliminate logic drift.
### Tier 1: Kernel & Micro-Kernel Substrate (Domain-Agnostic)
The Kernel is a purely generic application substrate. It is strictly forbidden from possessing domain knowledge about the "inSetu" product, Large Language Models, Context Gathering, or code editing. It provides purely agnostic I/O and orchestration via the standalone `akasa` kernel package.
* **`akasa` (Python Kernel Substrate):** Thread-local SQLite connection pooling (`akasa.db`), asynchronous Virtual File System queue and barrier locks (`akasa.vfs`), background worker metronome (`akasa.workers`), priority event bus (`akasa.hooks`), execution runners (`akasa.exec`), and the token gatehouse (`akasa.auth`).
* **`sutram` & `yenvui` (Frontend Micro-Kernel & Chassis):** Universal Web Component chassis, import map synthesis, Zustand UDF state management, and declarative URL hash routing.
* **Akasa Two-Phase Kernel Encapsulation (`configure_kernel` & `init_kernel_app`):** The web application chassis (`app.py`) must delegate resource limit tuning, security token gates, request teardowns, and HTTP cache suppression through the SDK membrane wrappers `configure_kernel()` (Phase A) and `init_kernel_app()` (Phase B), and invoke `boot_kernel()` for background execution workers to maintain structural symmetry and membrane isolation across development and production environments.
* **The Single-File Akasa SDK Membrane Mandate (`AKASA_MEMBRANE_ISOLATION`):** Direct imports from `akasa.*` framework modules are strictly restricted to exactly one designated membrane file: `insetu/core/sdk/__init__.py`. All other Tier 2 core substrate engines and Tier 3 domain extensions MUST import framework primitives, database accessors, VFS transaction handlers, and worker utilities exclusively from `insetu.core.sdk` or `insetu.core.utils_core`. Direct imports of `akasa.*` outside `insetu/core/sdk/__init__.py` are blocked by AST fitness validation.
* **The Single-File Frontend Membrane Mandate (`SUTRAM_MEMBRANE_ISOLATION`):** Direct imports from `'sutram'`, `'sutram-chassis'`, or `/static/vendor/sutram/*` outside of `insetu/core/system/insetu_sdk.js` are strictly banned. All Tier 2 core substrate components and Tier 3 domain extensions MUST import presentation primitives, state factories, styles, and utilities exclusively from `/static/extensions/system/insetu_sdk.js`. Direct imports outside this single-file membrane are blocked by JavaScript fitness validation.
* **Forwarding Header Membrane Mandate (`FORWARDED_HEADER_MEMBRANE`):** inSetu components, core engines, and extensions MUST NOT read client-identity forwarding headers (`X-Forwarded-For`, `X-Real-IP`, `Forwarded`, `HTTP_X_FORWARDED_FOR`, etc.) directly. The kernel peer classifier (`akasa.auth.peer.classify_peer()`), exposed through `insetu.core.sdk`, is the single source of truth for peer trust, socket loopback classification, and client IP extraction.
### Tier 2: Core Substrate Engines (The inSetu Workbench)
Tier 2 represents "inSetu proper." It builds the local-first AI Workbench product on top of the agnostic Tier 1 Kernel.
1. **Gather (`engine_gather.py`):** RAG context payload compiler, topology declaration broker, and differential context synthesizer.
2. **Yomama Sync Bridge (`engine_bridge.py`, `bridge_vfs.py`, `bridge_fuzzy.py`):** Multi-file `SEARCH`/`REPLACE` block parser, relative indentation healer, pre-flight AST syntax bouncer, and transactional patch ledger.
3. **VFS REST Gateway (`routes_fs.py`, `engine_fs.py`):** API transport layer that exposes the Kernel's VFS queue to the frontend via authenticated endpoints and multi-buffer projections.
4. **Cartographer (`cartographer.py`):** Repository topographer and deterministic `CODE_INDEX.md` architectural map generator.
5. **Offline Engine (`engine_offline.py`, `offline_ui.js`):** Stale-While-Revalidate GET request mirroring, IndexedDB outbox queueing, dead-letter queue, and two-stage outbox reconciler.
6. **LLM Gateway (`engine_llm.py`):** Universal multi-provider inference orchestrator supporting Anthropic, Gemini, and local CLI streaming adapters.
7. **Agent Harness (`engine_agent.py`, `agent.js`):** Autonomous ReAct orchestration engine integrating context packing, inference streaming, Yomama Bridge validation, and self-healing patch retry loops.
8. **Editor Substrate (`engine_editor.py`, `ui_editor.js`):** Dynamic CodeMirror language vendorization gateway, document typing, and multi-projection editor state management.
9. **Prompt Library (`engine_prompts.py`, `prompts.js`):** Core prompt management, virtual `.templates/` module prompt projection, and recursive `{{include_prompt: ...}}` macro resolution.
10. **Model Context Protocol Gateway (`engine_mcp.py`):** Model Context Protocol (MCP 2025-03-26) JSON-RPC 2.0 server exposing tools (`cartographer.extract`, `fs.fetch`, `bridge.sync`), resources, and prompts over HTTP (`/api/<workspace_id>/mcp`) and stdio transport.
11. **Remote Access Gateway (`engine_remote.py`):** Tier 2 core engine managing secure remote access, Tailscale WHOIS peer authentication (`classify_peer`), proxy header registration, and preview HTTPS tunneling.

### Tier 3: Domain Extensions
All other feature modules are Tier 3 Domain Extensions that plug into the core substrate via the `InSetuExtension` SDK and the synchronous/asynchronous Event Bus (`hooks` / `window.inSetu.events`):

## 1. Single Source of Truth (SSOT) & Spatial Physics
Logic, schemas, and configurations must exist in exactly one place. Redundancy breeds silent desynchronization across the local-first ecosystem.
* **The Configuration SSOT (`host.json` & `workspaces.json`)**: Daemon-level host configurations (server port bindings, watchdog flags, extension preloading, approved automation hook signatures) reside in `.insetu/host.json` (`get_daemon_host_config_path()`), while the multi-tenant workspace routing index resides in `.insetu/workspaces.json` (`get_system_index_path()`). Hardcoding references to legacy `system.json` outside of migration utilities is banned (`LEGACY_SYSTEM_JSON_BAN`). Workspace-specific and feature configurations must be managed statelessly via the `SettingsManager` using three strict scopes:
    * **`daemon`**: Global daemon preferences stored in `.insetu/host.json`.
    * **`workspace`**: Tenant-specific settings stored in `<control_dir>/workspace.settings.json`.
    * **`repo`**: Repository-specific settings stored in `<control_dir>/repo.settings.json`.
    * **`secure`**: Sensitive credentials encrypted via Fernet in `<control_dir>/secrets.json` using the global master key (`~/.insetu/master_key.txt`).
The OS kernel must never assume default namespaces or hardcode repository paths. Any operations mutating or re-indexing workspace environments or settings must explicitly invalidate centralized configuration caches (`_MUTATED_CONFIG_CACHE`) to prevent stale memory reads.
* **Defensive Configuration Fallbacks**: When extracting optional array or dictionary properties from workspace configurations or settings schemas, getters MUST enforce explicit non-None fallbacks (e.g. `(cfg.get('key') or [])`) to prevent `TypeError` exceptions during iteration when keys are explicitly set to `null` in JSON configurations.
* **Cache Invalidation Mandate**: Any service, extension manager, or route handler that alters application settings or writes configuration structures to disk must systematically clear internal memory caches to prevent desynchronization between active data stores and spatial realities.
* **The Topology Contract & Hierarchical VFS Sieve**: The codebase is not a database. `engine_topology.py` and its SQLite `topology_ledger` serve as the absolute Single Source of Truth for workspace file inclusion and sub-bucket mapping. Duplicating `os.walk` exclusion logic (e.g., ignoring `.git` or `node_modules`) inline in secondary scripts is strictly forbidden. Always query the `topology_ledger` or use the `vfs://` and `ctx://` URI schemes to safely route assets.
    * *Stage 1: Repository Sieve (Nullable Override Cascade & `.gitignore` Semantics):* `is_file_tracked_by_sieve()` evaluates repository files using a strict Nullable Override model (`repo_ignore_dirs`, `repo_ignore_files`, `repo_ignore_patterns`, `exts`, and `repo_managed_dirs` override global defaults when non-null, or inherit global baselines when `null`/omitted). All pattern evaluations (`matches_gitignore_patterns`) adhere strictly to standard `.gitignore` semantics: trailing slashes (`archived/`) match directory segments at any depth, leading slashes (`/build/`) anchor to the root, non-slashed globs (`*.pyc`, `.DS_Store`) match filenames or segments at any depth, `**` matches across directories, and `!pattern` negates previous matches sequentially.
    * *Stage 2: Sub-Bucket Sieve (`drop_patterns` vs. `ignore_patterns`):* When a file survives Stage 1 and matches a Sub-Bucket's `match_prefixes` or `dynamic_split_prefix`, `resolve_file_bucket()` evaluates two `.gitignore`-syntax filter arrays:
        1. **`drop_patterns` (Omit from Compilation & Diffs):** If matched, the file is routed to the reserved `_dropped` bucket (`exclude_from_context: True`, `exclude_from_diffs: True`). The file remains visible and editable in the VFS Explorer (`topology_ledger`), but is excluded from both the Sub-Bucket's context payload and Bucket 0 (`main`).
        2. **`ignore_patterns` (Pass-Through to Next Bucket / Bucket 0):** If matched, the Sub-Bucket yields the file (`continue`), allowing subsequent Sub-Buckets or the Bucket 0 (`main`) base pipeline to claim it.
    * *The Omniscient Exception (Yomama):* The Sync Bridge inherently bypasses strict Cartography filters to retain its ability to patch arbitrary filetypes not yet mapped to the configuration (e.g., Genesis patches). However, its sweeping logic must still be centralized in `utils_core.py` (e.g., via a dedicated `get_omniscient_workspace_files()` method) to enforce global system bans (like protecting `.git`) without duplicating raw `os.walk` loops inside route handlers.
    * *Version Control Topology Parity (VFS Git Status Reflection):* The physical file topology ledger (`topology_ledger`) must reflect working-tree version control status (`git_status`) directly in its index. Domain manifest serializers (`request_vfs_manifest`) and signature providers (`register_manifest_signatures`) must project git modification vectors (`git_modified`, `mod_cnt`) into partitioned VFS schemas, enabling presentation layers to render revision status statelessly without polling VCS binaries from the UI or route handlers.
* **DRY Utility Centralization**: Any structural framework logic required by multiple engines MUST be centralized in `insetu/kernel/utils.py` (Tier 1 Kernel utilities) or `insetu/core/utils_core.py` (Tier 2 Developer OS physics). Executing system commands or external CLI binaries MUST route through `execute_binary()` in `utils_core.py` or `ctx.exec.run()` to guarantee PATH, virtual environment (`sys.executable`), and desktop shell resolution.
"Fat Controllers" copying/pasting prefix logic are architectural failures.
* **Dynamic Working Directory Resolution (`get_daemon_cwd` / `set_daemon_cwd`)**: Modules and tests must never import `_cwd` by value (`BANNED_CWD_VALUE_IMPORT`) or mutate `._cwd` directly as a module attribute (`DIRECT_CWD_MUTATION_BAN`), as doing so desynchronizes Ring 0 context state from the `akasa.utils` facade. Always resolve the active working directory via `get_daemon_cwd()`, update it via `set_daemon_cwd()`, or reset test harnesses via `akasa.reset_state(cwd=..., control_dir=".insetu")`.
* **Sub-Field Setting Scope Inheritance**: When defining settings schemas containing nested sub-fields (`item_schema` on repeaters or `fields` on records), only the top-level setting field declares a `scope` (`daemon`, `workspace`, or `repo`). Nested sub-fields automatically inherit their parent's scope; declaring redundant `scope` attributes on sub-fields is ignored.
* **Single Patch Engine Invariant (`SINGLE_PATCH_ENGINE_INVARIANT`)**: In-memory block patch application logic must remain strictly centralized. `apply_block_in_memory` is defined exclusively in `insetu/core/bridge/bridge_fuzzy.py` and the zero-dependency `insetu/fallback_bridge.py` lifeboat.
* **Universal Repeater Secret Vaulting**: Setting schemas defining `type: 'repeater'` containing subfields with `secure: True` (such as `compute_endpoints` with `api_key`) MUST vault plaintext secrets into `.insetu/secrets.json` under `secrets[ext_name][f"{repeater_id}__{item_id}__{subfield_id}"]` and serialize them as masked `'********'` sentinels in configuration files, preventing credentials from persisting in plaintext across workspace settings.
* **Schema Repeater Identity Synchronization & Composite Target Bindings**: Repeater schemas managing identifiable records MUST declare `id_key` (e.g. `'id'`) and `slug_source` (e.g. `'title'`) to enable deterministic unique slug derivation (`_deriveUniqueSlug`), preventing ID collisions across additions and renames. Composite setting types (such as `target_binding`) combining parent-child selection vectors (e.g., `<endpoint_id>` and `<model_name>`) MUST encapsulate state into structured records (`{ endpoint, model }`) and resolve dependent option sets via contextual resolver callables rather than flat string concatenation.
* **Repository Data Containment Mandate (`.insetu-data/`)**: Domain extensions managing repository-scoped Markdown assets or persistent records within target repositories (e.g., `tracker` managing Kanban tickets, `notes` managing repository notes) MUST contain these assets under `<repo>/.insetu-data/<domain>/` rather than polluting repository root directories with ad-hoc dotfolders (e.g., `.tracker/`). Engines MUST maintain automatic backward-compatible migration (`move_tree_contents`) during Phase 1 boot, and MUST automatically exclude `.insetu-data/` sub-buckets from Git working tree diffs via `@hooks.on('mutate_workspace_config')` (ADR 0065).
* **Cryptographic Automation Execution Gating**: Extensions executing external host commands based on persistent file rules (e.g., `hooks`) MUST validate rule definitions against cryptographic SHA-256 command signatures recorded in `.insetu/host.json` (`get_daemon_host_config_path()`) under `approved_hooks`. Rules loaded from disk without active operator signatures must default to disabled status (`enabled = 0`).
* **The Artifact Parser Anti-Pattern**: Never parse generated output artifacts (e.g., compiled `.txt` diff dumps, RAG context payloads, or rendered UI strings) to determine system state or drive backend execution. Artifacts are strictly one-way projections for human or LLM consumption. Always query the underlying SSOT directly (e.g., executing `git status` via subprocess instead of reading a `_diffs.txt` file).
* **Stateless Multi-Tenancy & Scoped Request Routing**: The inSetu Workbench handles multiple tenant environments statelessly inside the REST layer via explicit tracking scopes.
Swapping profiles dynamically must occur via frontend headers or parameterized URL paths without backend process restarts.
All backend managers, hooks, and extensions must accept an explicit request-scoped `workspace_id` parameter and completely reject un-parameterized global state storage. All extension API endpoints must map the tenant context directly within the route template layout (`/api/<workspace_id>/ext_name/verb`) to ensure absolute path-level data isolation and eliminate leaky dependencies on header-sniffing.
* **The Canonical URI Boundary Mandate**: All internal filesystem, ledger, and event bus operations across both Python backend and JavaScript frontend MUST strictly utilize canonical, scheme-qualified URIs (`vfs://`, `ctx://`, `ws://`). Instantiating `InSetuURI` with naked or scheme-less path strings is strictly prohibited and raises a `ValueError`. Unsanitized strings originating from external ingress boundaries (such as LLM patch sandwiches, human search inputs, or route parameters) MUST be normalized immediately at the boundary using `InSetuURI.from_external_input(raw, default_scheme="vfs")`. Stripping URI schemes via `.replace()` or parsing paths using naive string split heuristics is banned.
* **Inter-Workspace Virtual Mounts (`ws://`) & Mutual Authorization Handshake**: Tenant workspaces may mount directories from peer workspaces read-only using the `ws://<workspace_id>/<domain>/...` URI scheme. Mounting requires an explicit bilateral policy handshake: the subscriber workspace MUST declare the mount in `shared_mounts` within `workspace.settings.json`, and the publisher workspace MUST declare the domain in `export_shared_domains` specifying permitted subscriber tenant IDs or the wildcard `'*'`. All VFS write-paths (saves, moves, archives, deletes, bulk mutations) targeting `ws://` URIs are rejected with HTTP 403 Forbidden. Mutations occurring in exported `ctx://` domains of publisher workspaces automatically broadcast synthetic `ws://` events to authorized subscriber workspaces for reactive RAG invalidation, guarded against recursive reentrancy loops.
* **Terminal Mark-and-Sweep Garbage Collection**: High-frequency context compilers and domain engines MUST NOT delete temporary artifacts prematurely during mid-flight compilation chains. Cache directory sweeping across `ctx://contexts`, `ctx://diffs`, and `ctx://workflows` MUST be registered under `@hooks.on('compilation_sequence_complete')` as a terminal mark-and-sweep garbage collection pass, executing only after all compilation DAG steps settle and flush chunks to disk.
* **The Multi-Phase Workspace Swap State Machine (`SessionOrchestrator` Mandate)**: Swapping active tenant workspaces MUST be governed by a discrete, synchronous 6-phase Finite State Machine (`LOCKED` → `TEARDOWN` → `IDENTITY_SWAP` → `HYDRATE` → `ROUTING` → `READY`):
    1. **`LOCKED`**: Locks application shell interactions (`_setAppShellLock(true)`), sets `isSwappingWorkspace: true`, and freezes the UI.
    2. **`TEARDOWN`**: Executes strictly under the *outgoing* tenant identity. Flushes dirty text buffers to the outgoing workspace, aborts in-flight network requests via `abortWorkspace(oldWs)`, purges Service Worker caches, and evicts all active spatial projections on `LayoutStore` with persistence suspended (`_suspendPersistence = true`) so the outgoing workspace's saved layout is not clobbered.
    3. **`IDENTITY_SWAP`**: Atomically updates `activeWorkspace` identity tokens in storage.
    4. **`HYDRATE`**: Coordinates tenant scope transitions through `StoreRegistry.beginScopeTransition(targetWs)`, re-binding and hydrating all tenant stores without cross-tenant bleed.
    5. **`ROUTING`**: Finalizes scope transition via `StoreRegistry.endScopeTransition()`, re-compiles layout shells, updates `window.location.hash`, and emits `insetu:soft-refresh`.
    6. **`READY`**: Unlocks the application shell (`_setAppShellLock(false)`) and returns `isSwappingWorkspace` to `false`.
    During active transition phases, the `shouldDropTenantEvent()` telemetry valve drops incoming SSE and event bus pulses to prevent cross-tenant state pollution.
* **Declarative Extension VFS Volume Mounting (`InSetuExtension(volumes={...})`)**: Domain extensions managing custom VFS volume schemes (e.g. `ctx://workflows`, `ctx://notes`) MUST declare their volume topology via the `volumes` dictionary on `InSetuExtension` rather than imperatively mounting drivers in boot hooks. The SDK automatically validates directory isolation, mounts drivers, registers `request_paths`, and executes legacy directory migrations (`move_tree_contents`) during Phase 1 boot.
## 2. The Data Layer & CQRS Mandate
inSetu operates directly on the user's hard drive. However, relying purely on raw filesystem I/O for high-velocity UI queries introduces unacceptable bottlenecks.
* **Markdown as an Artifact**: `.tracker/` markdown files are human-readable, Git-friendly *artifacts*, not the live application database.
* **The SQLite Cache Index**: Upon daemon boot, physical files are indexed into an embedded SQLite/DuckDB cache layer. All UI filtering, Kanban rendering, and API reads (`/api/tracker/files`) MUST query the fast SQL layer.
* **CQRS Write-Path Separation**: When a user drags a Kanban ticket, the API must perform the mutation against the SQL layer (for instant UI feedback) and dispatch a background worker task to asynchronously write the `.md` mutation to the physical disk.
* **Surgical Editing & O(1) Updates**: Global re-indexing (`DELETE FROM table` followed by bulk re-insertion) or complete DOM annihilation is strictly banned as a response to singular events. Event listeners must extract target boundaries and execute granular `INSERT OR REPLACE` or localized DOM reconciliation.
## 3. The Virtual File System (VFS) & Atomic Commits
The Yomama Sync Bridge is a surgical tool. Applying string patches blindly to disk creates half-patched, uncompilable codebases if an LLM hallucinates halfway through a transmission.
* **The VFS Matrix**: All incoming patch payloads must be staged entirely within an in-memory Virtual File System. 
* **The Pre-Flight Syntax Guardrail**: Before any file is flushed to physical disk, the VFS must run native syntax validation (e.g., Tree-Sitter AST validation with fallback to Python AST or Node V8 JS parsing) against the *completed* in-memory matrices. 
* **Optimistic Concurrency Control (OCC) & Deterministic 3-Way Merge**: File save mutations accepting an optional `base_hash` parameter verify physical disk parity prior to overwrite. If an out-of-band modification is detected (`current_hash != base_hash`), the backend inspects an in-memory ancestor ring buffer (`lookup_vfs_ancestor`) and runs an automated 3-way merge (`three_way_merge_text`). If concurrent edits affect disjoint lines, the transaction auto-merges, returns `status: "merged"`, and commits cleanly. Only true same-line collisions generate localized `.conflict_<timestamp>` fallback files and return HTTP 409 Conflict. Client buffers preserve `originalContent` and `baseHash` across offline outbox queueing, ensuring offline edits rebase cleanly upon reconnection.
* **Self-Healing JIT Artifact Resolution (`vfs_resolve_file` & `heal_missing_domain_volume`)**: When logical base context URIs (`ctx://contexts/`, `ctx://workflows/`) or multi-part chunks are requested via VFS read routes, the resolver must transparently map to the first valid chunk or dynamically trigger targeted on-demand recompilation via decoupled `heal_missing_domain_volume` event hooks if cache files are missing or cold. This eliminates read-time 404s while preserving lazy, non-blocking background compilation loops. Domain volume engines MUST subscribe to `@*.on('heal_missing_domain_volume')` to trigger targeted recompilation when their specific volume is queried.
* **Cartographer Hierarchical Path-Scoped Comment Preservation & AST Symbol Drift Watermarking**: Cartographer index mapping (`docs/CODE_INDEX.md`) MUST track comments using relative path hierarchies rather than raw basenames alone, ensuring identically named files in disparate directories (e.g. `__init__.py`, `core.py`) retain distinct comments without collision. Unchanged repository trees MUST bypass re-rendering and VFS saves via in-memory index content hashing (`_CARTOGRAPHER_SIG_CACHE`). Furthermore, Cartographer tracks public AST symbols in `symbol_ledger` (`body_hash` vs `verified_hash`). When a symbol's implementation changes while its documentation remains untouched, Cartographer MUST tag the index comment with a `[stale?]` sentinel until verified via `cartographer.verify_symbols` or updated by the developer.
* **Deferred Chunk Post-Valid Buffer Re-Evaluation & Fast-Tier Auto-Healing**: When a multi-chunk patch contains an anchor mismatch or overlapping replacement, the bridge MUST NOT abort the entire transaction immediately. The engine defers the failing chunk to the end of the file's patch list, commits the preceding valid non-overlapping chunks to the in-memory buffer, and re-evaluates the deferred chunk against the post-valid buffer. When `auto_heal` is active, the engine dispatches only the deferred chunk and the post-valid buffer to the Fast LLM tier to re-anchor the patch cleanly.
* **The VFS Deletion Mandate**: Deleting physical files or directories must strictly route through `ctx.vfs.delete(filepath)`. Passing leaky abstraction flags such as `ctx.vfs.save(..., data={"action": "delete"})` is permanently deprecated and blocked by AST fitness validation (ADR 0004, ADR 0018).
* **Module Template Immutability & Virtual Projection Parity**: Built-in module templates packaged within core or extension modules (`.templates/<mod>/`) and projected virtually under `ctx://prompts/.templates/<mod>/` are strictly read-only and immutable. The VFS write path MUST reject mutation attempts (saves, moves, archives, deletes) targeting read-only templates with HTTP 403 Forbidden. Operators customize built-in templates by using the `prompt-fork-template` action to fork them into sovereign workspace prompts (`ctx://prompts/`) or global user templates (`ws://default/prompts/.templates/user/`) (ADR 0064).
* **Dual-Representation Buffer & Macro Preview Contract (`prompts/resolve`)**: Editable VFS buffers (`vfs://`, `ctx://prompts/`) MUST always fetch raw, unexpanded source text from `/fs/fetch` so `{{include_prompt:...}}` and `{{ macro_* }}` directives are never destructively overwritten on save. On-demand macro-expanded previews (`toggleBufferPreview`) evaluate live unsaved buffer content in memory via `POST /api/<workspace_id>/prompts/resolve` in read-only mode (`previewMode: true`), while read-only templates default directly to macro-expanded preview mode.
* **Atomic Bulk Mutation Mandate (`fs/bulk`)**: Multi-item file mutations (bulk moves, bulk archives, bulk deletions) MUST NOT be executed via sequential client-side N+1 loops. Operations must be bundled into a single atomic payload dispatched to `POST /api/<workspace_id>/fs/bulk` and processed off-thread via `execute_vfs_bulk()` in the kernel (ADR 0063).
* **Atomic Rollbacks**: Transactions are atomic. If a multi-file patch is received and a single file fails syntax validation or diff anchoring, the entire VFS transaction is aborted.    
* **The Semantic Strategy Pattern**: The bridge must route patches dynamically based on syntax reality:
    * **Strict Engine**: `.py` and `.yaml` files use strict statistical ratio math and absolute step delta matching. Whitespace is law.
    * **Structural Engine**: `.js` and `.ts` ignore line breaks and pipe outputs through AST formatters (e.g., Prettier).
    * **Object Engine**: `.json` bypasses text diffs entirely, recursively applying object tree mutations.
    * **Fuzzy Engine**: `.md` and `.txt` utilize flattened Levenshtein distances to survive LLM token-wrapping hallucination.

## 4. Frontend: Unidirectional Data Flow (UDF)
The frontend UI must be highly resilient, reactive, and entirely decoupled from HTML DOM states.
* **The DOM Read Ban**: Modules (`kanban.js`, `bridge.js`) are strictly forbidden from reading state out of the DOM (e.g., querying `document.getElementById('...').value` or checking if an element `.classList.contains('active')` to determine business logic).
* **The Centralized Store**: The UI must operate as a pure function of a centralized state manager (Zustand or Vanilla PubSub in `store.js`). API payloads dispatch to the store; the DOM strictly subscribes to the store.
* **Selector-Scoped Store Subscription Mandate**: Monolithic store subscriptions (`this.subscribe(Store, state => { ... })` without selector functions) are strictly prohibited. Components MUST use selector-scoped subscriptions (`this.subscribe(Store, state => slice, (slice) => ...)`) configured with structural equality checks (`shallowEqual`) to prevent render thrashing across large manifest trees.
* **Domain Store Topology Isolation**: Domain stores (e.g., `GatherStore`, `GitStore`, `TrackerStore`) MUST manage ephemeral UI state only (e.g. `loading`, `searchQuery`). Duplicating global workspace topology or repository target configurations (`targetConfigs`, `allRepos`) into domain store state is strictly banned. Components must query `AppStore` or consume `this.ecosystem` reactively.
* **Dedicated Projection Pop-Out Windows**: Spatial viewport projections can be detached into standalone browser windows via `popoutProjection(filepath)`. Pop-out windows operate with minimal UI chrome (`variant="popout"`), communicate with parent and peer windows via `BroadcastChannel('insetu_telemetry')`, and execute direct network synchronization without opening duplicate Server-Sent Events (SSE) connections.
* **Child Viewport Presence Negotiation**: Detached pop-out windows MUST probe for parent windows via a `presence_ping` / `presence_pong` handshake over `BroadcastChannel('insetu_telemetry')`. If operating in standalone isolation without an active parent window, pop-outs lazily open a direct SSE stream to guarantee uninterrupted real-time telemetry (ADR 0063).
* **Spatial Projection Multi-Instance Identity & Sub-ID Hydration**: Viewport projections for multi-instance entities (e.g. text buffers, notes, tasks) MUST NOT hardcode singleton window identifiers (e.g. `id: 'notes:editor'`). Projections must be keyed by their canonical resource URI (`id: filepath`), enable `allow_popout: true` when detached rendering is supported, and resolve target resource paths reactively from `this.dataset.subId` to guarantee deterministic state hydration across spatial columns and detached pop-out windows.
* **Debounced Auto-Save & Emergency Teardown Flush**: Document buffer editors MUST implement debounced auto-saving (2000ms delay) to prevent I/O storming during active typing. Components must attach a `beforeunload` handler utilizing `fetch(..., { keepalive: true })` to guarantee unsaved in-memory edits are flushed to disk if the window is abruptly closed.
* **Truncated Buffer Read-Only & Save Guardrail**: When a text buffer exceeds memory display thresholds (e.g. 200KB) and is truncated with a UI performance notice, the editor MUST be strictly forced into read-only mode (`shouldBeReadOnly = !(isFS || forceEdit) || isTruncated`). Furthermore, file save transaction handlers (`saveBufferFile`) MUST explicitly verify `!state.isTruncated` prior to dispatching write payloads, preventing partial in-memory text from overwriting and corrupting full files on disk.
* **The "Full Refresh" Anti-Pattern**: UI state desynchronization (ghost tickets, orphaned modals) indicates a failure of the UDF contract. The system must natively heal its own state tree asynchronously without requiring the user to execute manual browser reloads.
* **Declarative URL Hash Routing SSOT**: Primary navigation, active sub-tabs, and deep workspace drill-down state MUST be driven strictly by `window.location.hash` (`#/{workspace_id}/{tab}/{sub-tab}/{deep_path}`) and mirrored reactively in `AppStore`. Direct reads or writes to `localStorage` for tab routing logic are strictly banned.
* **RFC 0108 Tab-Scoped Navigation State Mandate**: Storing global or monolithic directory navigation paths (`globalBrowsePath`, `currentBrowsePath`) in stores or components is permanently prohibited. Navigation state MUST be scoped per sub-tab using `AppStore.getState().getBrowsePath(subId)` and `setBrowsePath(pathArray, subId)`, isolating deep directory drill-downs across adjacent viewports and spatial projections.
* **Event Bubbling Teardown Safeguard**: Nested modal views and transient components MUST check `e.target === e.currentTarget` during close/teardown handlers to prevent event bubbling from child elements from accidentally triggering teardown loops in ancestor shells.
* **Event Path Resolver Mandate (`getEventPath`)**: Components and event listeners are strictly prohibited from calling `e.composedPath()` directly. All event target and bubble tree traversals must route through `getEventPath(e)` or `this.getEventPath(e)` via the SDK to ensure deterministic boundary resolution across nested Web Components and Shadow DOM roots.
* **Lit Template Safe Output & innerHTML Ban**: Direct binding to `.innerHTML` in LitElement render templates or injecting raw HTML strings into DOM elements is strictly banned. Components must render text nodes declaratively using Lit's native interpolation (which guarantees automatic XSS escaping) and style outputs via theme CSS tokens (e.g., `var(--intent-danger)`).
* **The Low Memory Footprint Mandate**: The client layer must remain low-overhead to protect performance on low-spec and mobile platforms. The frontend is strictly banned from executing memory-intensive text chunking, holding massive multi-megabyte string buffers, or iterating over large regex arrays on raw text. All parsing, slicing, and segmentation operations must be offloaded to backend pipeline processes.
* **Stateless Async Task Context Guards**: Long-running frontend job polling loops (`this.api.pollJob` / `window.inSetu.utils.pollJob`) and background event listeners must evaluate tenant workspace parity (`getActiveWorkspace()`) prior to executing progress, completion, or error callbacks. If the active tenant workspace shifts mid-flight, callbacks must be statelessly swallowed to prevent cross-tenant memory leakage or UI state pollution.
* **Spatial Viewport Projection Eviction Governance (`onEvict`)**: When windowed buffers, reports, or task projections pinned to `LayoutStore` close or evict, the originating domain store must register an `onEvict` schema in `createExtensionStore` to automatically reset transient state (e.g., active preview IDs, selected task pointers, editing buffers). Bypassing eviction schemas leads to ghost state hydration when projections are reopened.
### 4.1 Polymorphic Presentation Purity (The Card Action Mandate)
Custom dashboard extensions are strictly prohibited from writing custom contextual button rows or injecting free-form template strings directly into file list elements. All contextual entity interactions must register as structured `entityActions` configurations within the global registry to guarantee unified visual alignment and preserve layout integrity across workspace profiles.

### 4.2 Strict State Immutability & Reference Cloning

## 5. Asynchronous I/O & The Event Loop
inSetu runs via a local Python web server (Flask/Uvicorn). You must never paralyze the local event loop.
* **The I/O Block Ban**: Heavy workspace sweeps (e.g., parsing 500 files for Context Generation, executing blocking Git diff aggregations, spinning up cartography maps) MUST NOT block the main HTTP thread. All physical disk modifications, deletions, and massive multi-file collections must be executed through asynchronous off-thread background worker queues or pipelines.
* **Boot-Time Non-Blocking Mandate**: Handlers subscribing to `@hooks.on('system_boot')` MUST NOT execute synchronous heavy disk sweeps or blocking I/O passes. All boot-time indexing and context compilation routines must be dispatched off-thread via `submit_immediate_job` to guarantee sub-second HTTP port binding.
* **Browser HTTP Cache Lockdown**: Dynamic backend REST and HTML endpoints must enforce `Cache-Control: no-store, no-cache, must-revalidate, max-age=0` via global `@app.after_request` middleware. Dynamic responses must never rely on browser-level HTTP caching; offline persistence and asset caching are governed exclusively by the Service Worker lifecycle (`sw.js`).
* **Streaming Over Polling**: Offload these heavy generators into asynchronous background task queues. The frontend should connect via WebSockets or Server-Sent Events (SSE) to receive non-blocking, real-time status pulses (`"Compressing payload..."`, `"Mapping context..."`) rather than hanging on a 15-second HTTP request.
* **Full-Duplex Socket Isolation**: Extensions introducing persistent bi-directional streams (e.g., interactive PTY shells or real-time logs) must hook natively into the `flask-sock` interface exposed by the micro-kernel. WebSockets are strictly prohibited from spawning unmanaged long-running loops outside the ASGI thread coordinator, protecting the HTTP event loop from socket starvation.
* **Socket Teardown Mutex & Safety Guards**: Concurrent background worker threads writing to WebSockets (`ws.send()`) during client disconnects must wrap network output in thread locks (`threading.Lock()`) and evaluate socket state flags (`is_closing`). Unhandled network exceptions during socket teardown must be caught gracefully to prevent process thread leakage.
* **Abortable Synchronization Barriers**: Long-running background workers or thread pools waiting on asynchronous VFS queues must avoid indefinite blocking calls (like raw `queue.join()`). They must execute abortable event waiting against queued barrier sentinels (`action: "barrier"`) or polling checks that actively evaluate shutdown signals (`_VFS_SHUTDOWN_SIGNAL`) to ensure quick, safe teardowns during workspace switches.
* **Two-Stage Slew Limiter Pattern**: High-velocity file modifications (`vfs_mutated`) must be buffered into a fast event buffer (`topology_event_buffer`) for Stage 1 settlement before updating the physical index (`topology_ledger`). Heavy context compilers must listen exclusively to downstream resolved events (`topology_resolved`) with Stage 2 debouncing to prevent event loop thrashing during active editing.
* **Adaptive Polling & Push Stream Degradation**: When a real-time Server-Sent Events (SSE) or WebSocket push stream is active, client-side metronome polling loops MUST automatically degrade their interval (e.g., backing off from 3s to 30s) to minimize redundant HTTP REST requests while preserving real-time UI state updates.
* **Explicit One-Shot vs. Recurring Job Dispatch**: Background tasks scheduled in the worker ledger must explicitly communicate their execution lifecycle. Relying on implicit sentinel values (such as `interval_ms = 0`) at call sites is banned. One-shot delayed tasks MUST be scheduled via `submit_one_shot_job(job_id, ext_name, callback_name, delay_ms, ...)` to guarantee automatic ledger eviction upon completion and prevent infinite re-queuing. Recurring metronome tasks MUST use `submit_job(...)` with an explicit `interval_ms > 0`.
* **Declarative Compilation Step Anchoring & DAG Ordering**: Extensions registering background pipeline steps via `@hooks.on('register_compilation_steps')` MUST declare positional anchors (`"source"`, `"body"`, or `"sink"`) alongside integer `order` weights. Step resolution MUST delegate to `resolve_dag_chain(ctx, hook_name)` rather than implementing custom topological sort loops.
* **Worker Function Signatures & Job Category Tagging (`WORKER_CTX_FIRST_PARAM_MANDATE` & `WORKER_TYPED_SIGNATURE_MANDATE`)**: All worker functions decorated with `@<ext_bp>.worker` MUST declare `ctx` as their first positional parameter and provide explicit Python type annotations on all parameters (serving as the SSOT for synchronous contract validation). Overloading boolean flags with list payloads (e.g. `isinstance(force_full, list)`) is banned (`WORKER_PARAMETER_OVERLOAD_BAN`). Additionally, all calls to `ctx.jobs.submit()` or `submit_one_shot()` MUST explicitly declare `job_category` (`"ui_blocking"` or `"system_background"`), and `find_active_pipeline_job()` queries MUST pass an IoC `predicate=` callable (`FIND_ACTIVE_PIPELINE_JOB_PREDICATE_MANDATE`).
* **Aliased Inline Imports (Private Namespace Isolation)**: Inline imports inside function bodies are discouraged. When necessary to break cyclic import dependencies or defer optional runtime loads, they must be explicitly aliased with a leading underscore (e.g., `import module as _module` or `from pkg import helper as _helper`) to preserve private functional scope and satisfy the `UNALIASED_INLINE_IMPORT` AST rule.
* **Ephemeral WSGI Thread Handle Teardown (`teardown_appcontext`)**: Ephemeral WSGI request threads that acquire thread-local database connections must register `@app.teardown_appcontext` hooks to invoke `akasa.db.close_thread_connections()`, preventing unclosed SQLite connection leaks and WAL lock contention across high-frequency REST transactions.
* **System File Descriptor Hardening**: The web framework chassis must proactively inspect and raise POSIX soft file descriptor limits (`RLIMIT_NOFILE`) to at least 65,536 on startup to protect the daemon from socket and file descriptor exhaustion during concurrent compilation sweeps.
* **Process Memory, Thread Stack Sizing & Glibc Arena Management (`MALLOC_ARENA_MAX=2`)**: In multi-threaded Python daemons running background compilation chains, thread pool workers can trigger severe virtual memory fragmentation under glibc's default dynamic arena allocation ($8 \times \text{cores}$). System service units, CLI entrypoints, and daemon boot routines MUST enforce `MALLOC_ARENA_MAX=2` in the environment and constrain thread stack allocation via `threading.stack_size(1024 * 1024)` (1MB vs. glibc 8MB default) to bound virtual memory (`VmData`). High-frequency background workers must invoke `reclaim_process_memory()` (`ctypes.CDLL('libc.so.6').malloc_trim(0)`) following heavy compilation passes to return unmapped pages to the operating system.
* **Shared Kernel I/O ThreadPool Mandate (`SHARED_IO_EXECUTOR_MANDATE`)**: Ad-hoc instantiation of `concurrent.futures.ThreadPoolExecutor()` outside of the Akasa kernel (`__init__.py`, `hooks.py`) is strictly prohibited. Background concurrent I/O operations must route through `ctx.jobs.map_parallel()` or `akasa.workers.run_parallel()` to prevent unbounded thread sprawl and SQLite connection pool exhaustion.
* **Inference Admission Control Semaphores**: Multi-endpoint inference must enforce concurrency limits per compute endpoint via bounded semaphores (`_get_provider_semaphore`), clamping CLI adapters to 1 and local OpenAI-compatible endpoints to 2 to protect host queues from thread exhaustion.
* **Document-Only Routine Response Path**: Declarative agent routine `response_path` directives must strictly target document extensions (`.md`, `.markdown`, `.txt`, `.json`, `.yaml`, `.yml`, `.csv`). Directives targeting executable code files (`.py`, `.js`, etc.) are rejected with `PermissionError` to guarantee all code modifications route through `bridge.sync`.
* **Autonomous Routine Context Scouting & Handoff Transcript Parity**: When declarative agent routines execute without attached target files, routines MUST utilize fast-tier topology and code index scouting (`topology.overview` and `scout_targets`) and clamp discovered candidates against `topology_ledger` via `clamp_rag_files_to_topology()`. Furthermore, external LLM handoffs (`transport: manual` or `web_chat`) MUST preserve transcript purity by suppressing synthetic user messages on resume turns, and MUST decouple conversational prose from raw patch blocks, forwarding unapplied patches directly to the Yomama Bridge staging surface.

### 5.1 The Determinism Heuristic & Causal Synchronization Mandate
Relying on wall-clock time (`setTimeout`, `time.sleep`, or `Date.now() - ts < windowMs`) to coordinate state ordering, suppress event echoes, or guess when asynchronous I/O has settled is a critical architectural anti-pattern.
* **The Determinism Heuristic**: *If every timer duration (`delayMs`) across the codebase is changed to `0ms` or `60,000ms`, the system may run slower or more frequently, but it MUST NEVER produce a different final state, drop user input, or overwrite newer state with older state.*
* **Permitted vs. Banned Timer Usage**:
    1. **Slew Limiters & Batchers (Permitted):** Debouncers (`scheduleAutoSave`, `utils.debounce`, Stage 1/2 compilation slew limiters) that control *how often* work is dispatched while a deterministic state store or queue holds the authoritative state.
    2. **Transport & Liveness Timeouts (Permitted):** Bounding external I/O wait times (`AbortSignal.timeout`, SSE reconnect backoffs, Metronome visibility hibernation).
    3. **Ephemeral UI Cosmetics (Permitted):** Purely visual toast and status bar message decay with zero downstream data dependencies.
    4. **Procedural Ordering & Echo Suppression (Strictly Banned):** Using `setTimeout(..., 0)` to wait for component hydration, or using `Date.now() - lastSavedAt < X` / `time.time() - write_ts < X` to guess whether an incoming mutation event is a self-echo.
* **Read-Your-Writes VFS Overlay**: Because physical disk writes execute asynchronously on `_VFS_WRITE_QUEUE`, the VFS layer MUST maintain an in-memory pending-write overlay so that any `vfs.read()` or `GET fs/fetch` immediately following `vfs.save()` returns the newly staged content prior to physical disk flush.
* **Content-Addressed Causal Monotonicity (`base_hash` & `ancestorHashes`)**:
    * All `vfs_mutated`save receipts and events MUST carry the SHA-256 `base_hash` of the written content.
    * Native filesystem observers (`watchdog`) MUST suppress internal VFS write echoes by comparing on-disk SHA-256 hashes against the last VFS-written hash for that path rather than muting paths via arbitrary time windows.
    * Client editor buffers (`FsStore.activeBuffers`) MUST lock out inbound server reconciliations while local edits are uncommitted (`isDirty`), an autosave timer is scheduled (`autoSaveTimers`), or a save request is in flight (`savingPaths`), and MUST reject any fetched state whose hash is already present in the buffer's monotonic `ancestorHashes` history.
* **Relational Watermark Derivation (Deterministic CQRS Staleness)**: The application store MUST derive bucket and repository staleness (`dirtyBuckets`, `dirtyRepos`) purely reactively by comparing physical `vfs` bucket timestamps (`source_ts`) against compiled `ctx` artifact timestamps (`meta.timestamp`). Imperative addition or clearing of dirty sets via event bus callbacks is strictly prohibited. Modifying a file advances `source_ts` on the bucket, and successful context compilation sets `meta.timestamp >= source_ts`, settling the watermark deterministically.

1. **Structural Anti-Pattern $\rightarrow$ Static Fitness Function (`insetu/tests/fitness/`):**

2. **Behavioral Invariant $\rightarrow$ Parameterized Contract Test (`insetu/tests/unit/`):**

3. **Isolated Logic Flaw $\rightarrow$ Local Regression Test (`insetu/tests/unit/`):**

Tests must import the submodule explicitly (`from akasa.hooks import hooks as akasa_hooks`) and patch via `patch.object(akasa_hooks, "...")` to ensure deterministic symbol resolution across Python 3.10 and later runtimes.

## 8. Extension Coupling & Boundaries (`ctx.call` RPC vs. `ctx.emit` Pub/Sub)

Interactions across core engines and domain extensions follow a strict separation between **1:1 Typed Capability RPC (`ctx.call`)** and **1:N Lifecycle Pub/Sub (`ctx.emit`)**:

* **1:1 Capability Invocation (`ctx.call("<ext>.<action>", wait=True, **kwargs)`):** Used whenever a module or extension invokes a direct command or query on another module (e.g., `research` invoking `ctx.call("ingest.url", ...)` or `agent` invoking `ctx.call("llm.complete", ...)` and `ctx.call("bridge.sync", ...)`). Every capability is backed by a `TypedDict` schema, enforces workspace enablement (`is_extension_enabled`), and automatically awaits background `202 Accepted` jobs when `wait=True`.
* **1:N Lifecycle & IoC Aggregation (`ctx.emit`, `ctx.emit_first`, `ctx.emit_merge_list`, `ctx.emit_merge_dict`):** Used strictly for lifecycle broadcasts (`workspace_boot`, `topology_boot_complete`, `vfs_mutated`) and Inversion-of-Control plugin aggregation (`gather_declare_topology`, `register_compilation_steps`, `request_changelog_suggestions`).
* **Cross-Module Private Import Ban (`CROSS_MODULE_PRIVATE_IMPORT_BAN`):** Importing private underscore-prefixed symbols (`_helper`) across module boundaries is strictly banned by the AST fitness suite. Shared Tier 2 primitives belong in `insetu.core.utils_core` or `insetu.core.sdk`, and cross-extension invocations must route through `ctx.call()` and declare upstream hard dependencies in `__depends__`.
