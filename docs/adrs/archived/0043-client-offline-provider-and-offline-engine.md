# ADR 0043: Client Offline Provider, Service Worker Core, SutramDB Integration, and Core Offline Engine

## Status
Accepted (2026-09-04)

## Context
ADR 0008 established the theoretical framework for offline-first synchronization using an IndexedDB mutation queue and Service Worker. However, client-side REST interactions lacked a standardized network gateway capability to seamlessly intercept outbound requests, queue mutations when offline, and cache read-only GET payloads while maintaining Unidirectional Data Flow (UDF). Furthermore, network drops during boot caused unhandled fetch rejections and blocked the UI shell.
## Decision
1. **`OfflineHttpProvider` & `SutramDB` Gateway Integration (`api.js`):** Wrapped `window.inSetu.api.request` with `OfflineHttpProvider` and `SutramDB` from the Sutram micro-kernel[span_0](start_span)[span_0](end_span)[span_1](start_span)[span_1](end_span). GET requests employ a Stale-While-Revalidate caching pattern, while POST/PUT/DELETE mutations are written to an IndexedDB outbox queue with optimistic UI updates[span_2](start_span)[span_2](end_span).
2. **Two-Stage Outbox Drain Pattern:** `OutboxReconciler.drain()` executes two-stage cursor reads: pending mutations are read into memory in a `readonly` IndexedDB transaction before dispatching network requests, and then deleted in a separate `readwrite` transaction. This prevents IndexedDB `TransactionInactiveError` exceptions caused by awaiting asynchronous network fetches inside active IDB transactions.
3. **Differentiated Error Recovery (DLQ vs. 5xx Queue Halting):** Client errors (4xx / poison pills) are automatically isolated into the `dead_letter` IDB table, notifying the user via a UI Toast while allowing the remaining queue to continue draining cleanly. Server errors (5xx) or network drops immediately halt queue execution to preserve strict chronological mutation ordering.
4. **Reconciliation Locks & Service Worker Alignment:** While outbox draining is in progress (`isReconciling = true`), Service Worker `skipWaiting()` updates and server delta heartbeat polling (`checkManifestVersion()`) are locked out. This prevents incoming server deltas from overwriting optimistic UI states before outbox mutations settle.
5. **Binary Upload & Storage Quota Guardrails:** Binary `multipart/form-data` uploads (e.g., `/api/fs/upload`) are explicitly excluded from IndexedDB outbox queueing to prevent browser storage quota exhaustion.
6. **Network Hysteresis & Metronome Backoff:** Network recovery requires 3 consecutive successful ping responses (`NetworkHysteresisManager`) before toggling `isOffline` back to `false` and triggering an outbox drain. The frontend metronome observes `document.hidden` via the Visibility API, backing off polling ticks from 100ms to 60,000ms when backgrounded.
7. **Declarative `offline_mode` Contract:** Extensions declare an `offline_mode` attribute in `ExtensionRegistry` (`"full"`, `"read_only"`, or `"none"`)[span_3](start_span)[span_3](end_span). The API gateway evaluates this flag to determine whether offline mutations are enqueued or rejected[span_4](start_span)[span_4](end_span).
8. **Core Offline Engine & Telemetry UI (`offline_ui.js`):** Built a dedicated Tier 2 core extension providing `OfflineStore` and UI components (`InSetuCoreOfflineLedger`, `InSetuCoreOfflineSettings`, `InSetuCoreOfflineLog`) to inspect outbox mutations, manage per-repo offline capability toggles, pre-cache repositories, and view real-time telemetry logs[span_5](start_span)[span_5](end_span). Connected outbox tracking to UI elements (e.g. rendering '🌩️' icons for files with pending outbox mutations)[span_6](start_span)[span_6](end_span).
9. **Offline Boot Hydration & In-DOM Security Gate (`app.js`):** Configured `executeBootSequence()` to hydrate workspace topologies, configurations, and manifests from `localStorage` during offline sessions[span_7](start_span)[span_7](end_span). Replaced native browser `prompt()` dialogs with an in-DOM HTML modal during 401 security challenges and enabled fast-track offline authentication against cached `localStorage` tokens[span_8](start_span)[span_8](end_span).

## Consequences
* **Positive:** Full offline-first resilience for supported extensions without blocking the UI or losing uncommitted edits.
* **Positive:** Complete visibility into IndexedDB outbox queues, dead-letter queues, and network telemetry.
* **Positive:** Deterministic, zero-data-loss outbox draining upon network reconnection via `OutboxReconciler.drain()`.
* **Negative:** Extensions must explicitly declare their `offline_mode` intent to participate in offline queueing.
