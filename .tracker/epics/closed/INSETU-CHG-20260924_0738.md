## Description
* **Parallel Cartography Execution (`cartographer.py`)**: Refactored `map_repositories` to execute repository index mapping in parallel using a `ThreadPoolExecutor(max_workers=5)`, significantly reducing latency during full multi-repo context sweeps[cite: 3]. Updated the cartographer DAG compilation step to anchor to `body` (order 15) and depend explicitly on `topology_scan`[cite: 3].
* **VFS Error Telemetry Propagation (`engine_fs.py`)**: Injected global background system error telemetry (`hooks.emit_background('system_error', ...)`) with full tracebacks into all primary VFS REST route exception handlers (`api_fs_move`, `api_fs_archive`, `api_fs_delete`, `api_fs_save`) to ensure silent backend failures are captured[cite: 3].
* **Pipeline State Alignment (`engine_system.py`, `system.js`, `api.js`)**: Renamed the system telemetry `is_compiling` boolean to `is_pipeline_active` to accurately reflect generic DAG pipeline execution[cite: 2]. Restricted UI job progress spinners in `api.js` to only handle `ui_blocking` tasks that are explicitly defined as pipeline jobs (`topology`, `cartographer`, `gather`, `git`, `flow`)[cite: 3].
* **UI Compile Trigger Decoupling (`fs.js`, `gather.js`)**: Eradicated manual `executeCompile()` triggers from VFS UI file operations (`uploadFileToWorkspace`, `refreshActiveFileViews`) and Gather quickpack actions[cite: 3]. The system now correctly relies on the automated DAG topology settlement hooks (`topology_resolved`) to cascade compilation tasks, enforcing strict Inversion of Control.
* **DAG State Deltas Migration (`engine_gather.py`)**: Updated `_background_compile` to return `state_deltas` in its artifact payload instead of passing `next_kwargs` directly into the worker chain, aligning with the generic Akasa DAG orchestrator[cite: 3].
