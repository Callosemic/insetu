## Description
Currently, `insetu/cartographer.py` utilizes a localized `try/except RuntimeError` wrapper to catch "shutdown" signals and prevent noisy errors when submitting background jobs during a workspace OS swap. 

To maintain the "Pit of Success" architecture for extension developers, this logic should be generalized and pushed down directly into the `submit_immediate_job` utility inside `insetu/workers.py`. By absorbing this thread-pool shutdown race condition at the ledger level, we eliminate the need for downstream extensions to individually handle daemon termination lifecycle quirks.

## Acceptance Criteria
* Refactor `submit_immediate_job` in `insetu/workers.py` to gracefully catch and absorb `RuntimeError` exceptions containing "shutdown".
* Have the utility return a boolean (or log a silent warning) instead of bubbling the exception up to the caller.
* Remove the localized `try/except` fallback logic currently residing in `cartographer.py`.
* Audit other core engines to ensure they aren't manually catching this same exception.
