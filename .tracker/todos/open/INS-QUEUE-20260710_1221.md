## Description
quick-packs should store the rule: what is added to it, e.g. a folder, a file, a context, etc. then the quickpack is assembled JIT.

maybe there should be a standardized way for extensions to present their cards to the os as pointers to a type of data/data-container/action. currently, what are the data container types we have:

1) files
2) folders
3) contexts
4) bespoke actions 

does that cover everything?

this way, hooks into cards can receive that pointer, and if it's faves, then it pins them to a list. if it's quick-packs, then it can add them to a pack (rejecting actions).
