## Description
The REST interface layers are scaling rapidly across modular blueprints and extension layers, but the workspace currently lacks an interactive or machine-readable capability map. Generating a structured OpenAPI/Swagger specification is critical—not for human interface views, but to provide a deterministic route and parameter map for collaborating LLMs to navigate system capabilities safely.

## Action Items
- [ ] **Enforce Docstring Contract Standards:** Standardize documentation layout blocks across all active Flask blueprints (`routes_fs.py`, `routes_bridge.py`, `engine_tracker.py`, etc.) detailing precise parameter variables, accepted header definitions, and response schemas.
- [ ] **Develop an Offline Spec Sweeper:** Build a zero-dependency build-time utility module (e.g., `utils_openapi.py`) that uses Python's native `ast` and inspection frameworks to crawl active blueprints.
- [ ] **Compile Static Contract Artifacts:** Integrate the extraction script straight into the core RAG context gather execution lifecycle (`engine_gather.py`). Every time the workspace compiles its context trees, it must output a clean, static `.insetu/data/openapi.json` file.
- [ ] **Zero Runtime Footprint:** Ensure the spec engine remains an offline compile-time projection, entirely free from heavy external runtime dependencies (like `flasgger`) to safeguard micro-kernel boot performance.
