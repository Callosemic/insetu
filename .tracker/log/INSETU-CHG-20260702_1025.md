## Description
Following the ratification of the UI Design Standards, several layout and presentation layers require coordination to ensure systemic stability, maintainability, and strict adherence to the DRY (Don't Repeat Yourself) principle.

* **View Factory Migration (Structural Integrity):** The current `UIFactory.createModal` method applies a constrained, boxed layout uniformly to all dynamically generated interfaces. To adhere to the *Fullscreen View Paradigm*, we must evolve this utility to differentiate between transient pop-ups (modals) and parallel workspaces (views). High-density interfaces such as the Batch Workflow (`batch-modal`), Browse Files (`browse-modal`), and Research Preview (`rs-preview-modal`) must be migrated to edge-to-edge canvases.

* **Centralized Overflow Monitoring (DRY Coordination):** The `ResizeObserver` utilized for responsive toolbar wrapping is currently hardcoded as an inline `<script>` within `index.html`. To encourage a Single Source of Truth (SSOT), this observer must be abstracted into a generalized `window.inSetu.ui.OverflowMonitor` utility. This will allow the system to seamlessly apply responsive truncation to any action array (e.g., `.modal-footer`, `.tasks-controls`) simply by appending a semantic class like `.ui-responsive-toolbar`.

* **Semantic Theme Tokens (Visual Resilience):** Throughout the JavaScript extension modules (`ext_tracker.js`, `ext_citations.js`, `fs.js`), there is an abundance of inline, hardcoded hexadecimal colors (e.g., `#10b981`, `#ef4444`, `#8b5cf6`) applied directly to DOM elements. To comply with the *Theme Variables & Contrast* standards, these must be swept and replaced with CSS variables (e.g., `--intent-success`, `--intent-danger`, `--intent-primary`) defined centrally within `style.css`. This guarantees high-contrast legibility across Light, Dark, and E-Ink modes without requiring manual JavaScript overrides.
