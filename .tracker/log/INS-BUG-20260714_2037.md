## Description
In early iterations, repository filters (e.g., `pinnedRepos`) functioned as naive text-matching against card titles or descriptions. This caused false positives and missed cards that represented repo buckets/sub_buckets but didn't explicitly include the repository name in their primary text.

## Notes / Execution Log
* **Resolution (2026-07-15):** Injected strict `repos` array and `repo` string attributes into the manifest metadata payload during compilation in `engine_flow.py` and `engine_git.py`. 
* Refactored frontend filtering logic in `ext_flow.js` and `ext_git.js` to strictly evaluate `manifest[filename].meta.repos` or `manifest[filename].meta.repo`, establishing deterministic repository boundaries for the UI filter pills and eliminating text-matching hallucinations.
