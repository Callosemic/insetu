## Description
**[Step 1 of the V2 Migration Sequence: The Sockets]**

Refactor `window.ExtensionRegistry` to support declarative UI hooks (e.g., `registerUIHook('zone:file-card-actions', ...)`). This will allow plugins to dynamically inject their own UI components into specific application zones, receiving the active `ExecutionContext` payload, without hardcoding them into the core OS.

* **Backend Requirement:** Build `insetu/hooks.py` (the Event Bus) to support `@hooks.on` lifecycle events like `mutate_workspace_config`.

**Dependency Management Strategy:**
When mounting heavier backend extensions, the OS kernel should *not* attempt to auto-install missing Python packages. Instead, the `load_workspace_extensions` routine should gracefully catch `ImportError`s, skip the extension mount, and broadcast a warning to the console/UI. This enforces a developer-centric, strictly opt-in dependency model.
## Notes / Execution Log
* **Resolution:** Engineered `hooks.py` to serve as the Singleton Event Bus for the micro-kernel. Added `registerSettingsAction` and `registerSubTab` to the frontend `ExtensionRegistry` to decouple DOM injections.
