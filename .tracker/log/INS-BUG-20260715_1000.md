## Description
extensions that aren't active in the current workspace still have their variables and settings appearing in the main system settings modal
## Notes / Execution Log
* **Resolution (2026-07-27):** Resolved via strict Unidirectional Data Flow (UDF) extension filtering[cite: 9]. The `autoWireSettingsSchemas` and `_settingsActions` generation in `app.js` now explicitly checks `window.ACTIVE_EXTENSIONS.includes(extName)` before injecting settings into the modal[cite: 9]. Extensions inactive in the current tenant are mathematically blocked from rendering settings[cite: 9].
