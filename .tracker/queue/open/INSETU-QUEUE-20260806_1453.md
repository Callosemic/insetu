## Description
This epic tracks the cleanup of several architectural anti-patterns and DRY violations bleeding across the ecosystem:

### 1. The File Size Calculation Clones
* **Issue:** Hardcoded mathematical blocks used to compute `sizeStr` from `meta.chunk_sizes` and `meta.size_bytes` are duplicated in `ext_gather.js`, `ext_flow.js`, and `ext_git.js`.
* **Action:** Extract this logic into `sutram/js/utils.js` as an agnostic `formatBytes(meta)` utility and expose it via the SDK.

### 2. Rogue \`while(true)\` Polling Loops
* **Issue:** `fs.js` (`executeDeepLinkSearch`) and `ext_citations.js` (`_openCitationNotes`) execute manual `while(true)` loops to hit the `/jobs/` endpoint, risking memory leaks and blocked UI threads.
* **Action:** Replace these unmanaged loops with the native `this.api.pollJob` wrapper.

### 3. Cross-Extension Bucket Resolution Shims
* **Issue:** Core ecosystem topology math (`getFlattenedBuckets`) is housed inside the `gather.js` extension, forcing `ext_tracker.js` and `ext_notes.js` to rely on brittle `window.inSetu` namespace shims.
* **Action:** Hoist the `getFlattenedBuckets` engine into `sutram/js/utils.js` or `core/sdk.js` to provide a clean, centralized API.

### 4. Boilerplate Frontmatter Serialization
* **Issue:** `ext_tracker.js`, `ext_skills.js`, and `ext_notes.js` manually map internal form states to YAML strings inside `_onRequestFrontmatter` event handlers.
* **Action:** Expose a generic `bindStoreToYaml` mapping utility to consolidate data-marshalling logic and reduce component clutter.
