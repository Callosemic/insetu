## Description
To provide granular, atomic reversion between Git commits, we must implement a databased ledger of Yomama patches. This serves as a highly surgical "undo" tree for LLM hallucinations or logic drift that occurs before a developer is ready to formally stage and commit their working directory.

This is strictly an ephemeral patch history, not a secondary version control system. 
### Execution Blueprint
1. **The SQLite Ledger (`bridge.db`):** Create a new table tracking `patch_id`, `repo`, `filepath`, `search_block`, `replace_block`, `post_patch_hash`, `timestamp`, and `ttl_expires_at`.
2. **The Sync Intercept:** Update `execute_bridge_sync` in `engine_bridge.py` to calculate a SHA-256 hash of the target file's content immediately *after* the patch is verified. Write the patch matrices and this hash into the ledger prior to the VFS commit.
3. **The Git Push Hook:** Update `api_git_push` in `engine_git.py` to broadcast a `post_git_push` event over the Event Bus upon a successful remote sync.
4. **The TTL Expiration:** The Bridge extension listens for `post_git_push` and updates all active ledger entries for that repository with a `ttl_expires_at` timestamp (e.g., NOW() + 48 hours). 
5. **The Metronome Sweep:** A background worker routine periodically sweeps the `bridge_ledger` table, permanently dropping rows where `NOW() > ttl_expires_at`, keeping the SQLite footprint mathematically bounded and preventing infinite disk bloat.
6. **The History UI:** Register a new `History` sub-tab under the `Edit` workspace via `ExtensionRegistry.registerSubTab()`. This view queries the SQLite ledger and displays recent patches in reverse-chronological order (newest first). 
7. **The Drift Guardrail:** When "Revert" is clicked, the backend hashes the live file on disk. If it does not match `post_patch_hash`, the UI flags a warning: *"Manual edits detected since patch. Yomama will attempt a surgical revert."*
8. **The Mathematical Revert:** If approved, the function seamlessly inverts the `search_block` and `replace_block` strings and pipes the payload directly back into the existing VFS Sync Bridge pipeline. If the user altered the patched lines, the Bridge will safely fail and refuse to corrupt the file.
