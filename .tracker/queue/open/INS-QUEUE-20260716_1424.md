## Description
Following the graduation of the extension ecosystem to the Polymorphic Entity-Action Card Registry (ADR 0023), the action resolution logic is currently localized inside the `<insetu-card>` component. To achieve perfect Inversion of Control and DRY compliance, we must extract this logic into a globally available SDK primitive: `<insetu-action-bar>`.

By pushing this down into the SDK, future complex visual entities (tables, grids, context panes, and deep file trees) can effortlessly inherit the exact same action routing, loading spinner states, and CSS-order sorting without duplicating the resolution loop.

### Action Items
- [ ] **Create `<insetu-action-bar>` (in `sdk.js`)**: 
  - Construct a stateless Web Component that accepts `entityType` (String) and `entityData` (Object) as properties.
  - Port the `ExtensionRegistry.getEntityActions` mapping and filtering logic from `<insetu-card>` into this new component's `render()` method.
  - Implement the `<insetu-async-btn>` and standard `<button>` declarative rendering patterns based on the `act.asyncAction` or `act.onClick` intent configurations.
- [ ] **Refactor `<insetu-card>` (in `ui_file_tree.js`)**: 
  - Strip the manual `_renderDynamicActions()` or inline loop logic.
  - Drop `<insetu-action-bar .entityType=${this.entityType} .entityData=${this.entityData}></insetu-action-bar>` directly into the card's action overlay slot.
- [ ] **Verify Layout Integrity**: Ensure that the CSS `gap: 6px` and `order: X` flexbox properties function perfectly within the new component shadow DOM and that dropdown z-indexing remains undisturbed.
