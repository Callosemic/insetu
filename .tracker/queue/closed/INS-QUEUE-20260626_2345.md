## Description
**[Step 2 of the V2 Migration Sequence: The Great Decoupling]**

Pivot the inSetu OS to a strict Micro-Kernel architecture. The core chassis should exclusively contain the RAG Context Gatherer and the Yomama Sync Bridge. Project management (Kanban Tracker), Git Operations, and the Cartographer must be extracted into completely optional extensions.

*Crucial Constraint: Do not optimize the state or data layers yet. Just migrate the boundaries.*

**Execution Blueprint:**
1. **Backend Blueprinting:** Extract `engine_tracker.py` and `engine_git.py` into Flask Blueprints that only mount if declared in the `config.json` extensions array.
2. **Context Hooks:** Remove hardcoded `.tracker/` folder lookups from `engine_gather.py`. The Tracker extension must independently inject its `.tracker/` virtual sub-buckets into the RAG compiler via the `@hooks.on('mutate_workspace_config')` event bus.
3. **Frontend Decoupling:** Remove hardcoded HTML for the "Tasks" tab from `index.html`. Utilize `window.ExtensionRegistry.registerTab('tasks', 'Tasks')` inside `kanban.js` so the UI only renders if the extension is active.

By doing this, enterprise teams with entrenched issue trackers (e.g., Jira, Linear) can use inSetu's VFS patching and context generation with zero UI bloat or workflow lock-in.
